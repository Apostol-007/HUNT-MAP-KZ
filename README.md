# HUNT MAP KZ — работающий код прототипа / частичная реализация ТЗ v1.0

Нативные iOS исходники + тестируемое геометрическое ядро + тестируемый серверный прототип. Внимание: **это не готовое полевое приложение и не карта охотугодий Казахстана**. Полный статус: [docs/IMPLEMENTATION_STATUS.md](docs/IMPLEMENTATION_STATUS.md).

## Структура
- `Core/` — Swift Package HuntCore, геометрия и движок геозон; Swift Testing.
- `iOS/` — iOS 17+ SwiftUI приложение, схема офлайн, GPS, предупреждения, маршруты, маркеры, GPX и GeoJSON.
- `server/` — FastAPI API каталога и доставки пакетов с Range/SHA256; без фиктивной публикации реальных границ.
- `docs/` — результаты запуска тестов и ограничения.

## Запуск тестов на Windows/Linux/macOS с Swift 6+
```bash
cd Core
swift test
```

## Запуск сервера на Windows (PowerShell)
```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r server\requirements.txt pytest httpx
.venv\Scripts\python.exe -m uvicorn server.app:app --host 127.0.0.1 --port 8000
```
Открыть `http://127.0.0.1:8000/docs`. Для тестов `.venv\Scripts\python.exe -m pytest server/tests -q`. Запускать из корня HUNT_MAP_KZ_MVP.

## Сборка iOS на Mac
Нужен macOS, Xcode, XcodeGen. Из каталога `iOS/` выполнить:
```bash
xcodegen generate
open HuntMapKZ.xcodeproj
```
Выбрать физический iPhone, свою Development Team и нажать Run. Пакет `HuntCore` подключен локально, внешний SDK пока не требуется. Права GPS запрашиваются внутри приложения. **Xcode-сборка не проверена**; сообщения компилятора нужно устранить перед релизом.

## Проверка MVP вручную
1. Открыть «Карта» и нажать GPS, проверить точность GPS.
2. Во вкладке «Загрузки» импортировать собственный GeoJSON FeatureCollection с Polygon/MultiPolygon, либо включить тестовый полигон.
3. На вкладке «Карта» начать запись, добавить маркер, сделать несколько перемещений, остановить маршрут.
4. В «Маршруты» экспортировать GPX. В «Маркеры» поделиться геоссылкой.
5. Включить авиарежим и убедиться, что геометрия, сохранённые маркеры и маршруты доступны без сети. **Топографической подложки пока нет**.

### Формат импортируемой границы
FeatureCollection, `features[].geometry.type` = `Polygon` либо `MultiPolygon`, координаты `[longitude, latitude]`. `properties.name` — подпись, `properties.kind` = `huntingGround` или `protectedArea`. Все импортированные объекты принудительно получают `verified=false`.

## Данные
Реальные полигоны, спутниковые снимки, фото животных и офлайн-тайлы в проект не включены: права и точность требуют подтверждения. Синтетическая демонстрация НЕ отражает реальную юридическую границу охотничьего угодья.

## Инкремент v0.2 — локальные растровые MBTiles (19.11.2026)

В `iOS/HuntMap/OfflineTiles.swift` добавлен клиент публичного HTTPS-каталога пакетов, скачивание во временный файл, **потоковая проверка SHA-256**, контроль свободного места, валидация формата растрового MBTiles, атомарная установка и реестр установленных пакетов. В `OfflineMapView.swift` реализована подача XYZ-тайлов из локальной SQLite MBTiles через `MKTileOverlay` без remote tile URL. Отдельная вкладка «Загрузки» предлагает три **области выбора**: `region`, `ground`, `country`. Это маршруты каталога, а не утверждение о существовании реальных карт для каждой области.

**Важно:** в этом инкременте применён встроенный **MapKit/MKTileOverlay вместо запланированного MapLibre**. Он позволяет отработать конвейер локальных MBTiles без внешней зависимости, но требует переноса на MapLibre или сетевой инструментальной проверки строгого офлайн-режима. MapKit может инициировать вспомогательные запросы Apple, поэтому соответствие требованию «ни одного сетевого вызова» пока **не доказано**. При отсутствии пакетов приложение отображает прежнюю схематичную Canvas-карту, а не загружает онлайн-подложку.

Серверная команда для публикации **заранее законно полученного** raster MBTiles:

```bash
cd HUNT_MAP_KZ_MVP
python -m server.publish_mbtiles --file /path/to/licensed.mbtiles --pack-id oblast-2026-v1 --scope region --scope-id region-identifier --license 'EXACT_GRANTED_LICENSE' --version 2026.11
python -m uvicorn server.app:app --host 127.0.0.1 --port 8000
```

Для установки с iPhone необходим HTTPS-сервер, доступный телефону, и реально опубликованный файл с указанным ID. Сам по себе локальный HTTP-сервер разработчика не удовлетворяет клиентской политике HTTPS. Назначение лицензии не подтверждает юридические права автоматически: перед публикацией оператор обязан проверить допустимость офлайн-копирования и распространения. Пакеты `raster-mbtiles` поддерживают PNG/JPEG/WebP по метаданным формата; визуальный декодер iOS для WebP отдельно не тестировался. Для предсказуемого результата отдавайте PNG/JPEG.

**Пределы v0.2:** пока отсутствуют законные геоданные реальных охотугодий, спутниковые снимки 1 м/пиксель, векторные карты, дедупликация перекрывающихся MBTiles, докачка после обрыва, криптографическая подпись манифеста, аутентификация/синхронизация, ETL животных, офлайн-полевые испытания, сборка на macOS. Полная загрузка MBTiles повторно скачивает файл после обрыва; не заявляется как resumable. Сервер отдаёт файл потоково, но для каждого запроса предварительно пересчитывает SHA-256 всего файла (дорого для гигабайтных пакетов); в production нужны доверенный immutable object storage и проверка при публикации. Не используйте приложение как источник юридических разрешений на охоту.

## Обновление v0.4 (19.11.2026)

MapKit-карта заменена на MapLibre Native iOS. Установленные растровые MBTiles подключаются через локальный `mbtiles://` источник; пустой офлайн-стиль не ссылается на интернет-карты. Поддержан импорт пользовательского `.mbtiles` через Files на iPhone. Подробнее: `docs/RELEASE_v0.4.md`.

ВНИМАНИЕ: исходники не собраны на Xcode и не испытаны на iPhone. Тесты Swift Package (`Core`) и FastAPI не покрывают сборку iOS UI.

## v0.5 — офлайн-каталог животных
Вкладка «Животные» принимает локальные JSON-пакеты с источником, лицензией, датой и доказательностью по каждому виду. Импорт через Files; данные остаются на устройстве и работают без интернета. Пример **полностью вымышленного** пакета: `examples/wildlife-schema-example.json`. Точные координаты видов в пакетах запрещены. Спецификация, статус проверок и ограничения: `docs/RELEASE_v0.5.md`.

## v0.7 — GBIF candidate ETL (ручное формирование, не автоматическая публикация)

Новый модуль `server/gbif_etl.py` собирает ограниченную выборку GBIF внутри проверенной геометрии угодья, фильтрует записи с неподходящей лицензией, некачественными/скрытыми координатами и дублями и формирует предложение JSON для **обязательной ручной проверки**. Не включает реальные данные животных или границы угодий в поставку. Руководство и ограничения: `docs/RELEASE_v0.7.md`.

```bash
python -m pip install -r server/requirements.txt pytest httpx
python -m pytest -q server/tests
python -m server.gbif_etl --boundary /path/to/verified-ground.geojson --output /path/to/review-candidate.json
```

## Обновление v0.8: импорт границ GeoJSON

Добавлен проверяемый серверный конвейер подготовки GeoJSON с контролем источника, датой актуальности, ограничениями геометрии, SHA-256 и требованием ручного подтверждения публикации. API: `/v1/catalog/grounds`, `/v1/grounds/{ground_id}`, `/v1/grounds/{ground_id}/geojson`. Локальный iOS-импорт принимает `Feature` и `FeatureCollection`. **Все импортированные границы отмечены как юридически не подтверждённые.** Инструкции и фактически выполненные тесты: `docs/RELEASE_v0.8.md`.
