# HUNT MAP KZ v0.7 — GBIF candidate ETL

Дата: 19.11.2026. Статус: предварительный ETL-процесс, не опубликованная база животных. Сборка iOS на macOS/Xcode и полевые испытания отсутствуют.

## Изменения

- `server/gbif_etl.py`: ручной CLI, запрос GBIF occurrence/search c WKT прямоугольником охотугодья и последующей локальной проверкой попадания внутрь геометрии (включая отверстия), обязательная проверка метаданных границы.
- Жёсткий лимит количества записей: импорт неполного результата запрещён; большие угодья нужно разделять на части/использовать соответствующий согласованный источник данных и реализовать отдельно полноту извлечения.
- Отсекаются записи без явной CC0/CC BY лицензии, с отсутствующей погрешностью, чрезмерной неопределённостью (по умолчанию более 1000 м), ошибками координат, метками скрытия, сомнительным таксоном, дубликаты GBIF key, записи вне границы или в буферной зоне.
- Группировка по GBIF `taxonKey`, выводит агрегированные записи, число свидетельств и ссылку на одну исходную запись, **без координат**. Статусы `probable`/`historical` — предварительная техническая классификация, не доказательство стабильного обитания или права охоты.
- Выход: `<output>.json` и `<output>.review.json`; автоматическая публикация на API **не производится**. Необходим человек-модератор, проверка правообладателей/атрибуции, политик чувствительных видов, качества границы и необходимости исключить отдельные виды.
- В `server/requirements.txt` добавлена библиотека Shapely с фиксированной версией.

## Запуск

Из корня каталога проекта:

```bash
python -m pip install -r server/requirements.txt pytest httpx
python -m pytest -q server/tests
python -m server.gbif_etl --boundary /path/to/verified-ground.geojson --output /path/to/gbif-proposal.json --max-records 1000
```

`verified-ground.geojson` должен быть GeoJSON Feature с Polygon/MultiPolygon, Properties: `ground_id` (строка), `boundary_verified: true` (после **реальной ручной проверки**), `source_url` (официальный HTTPS-источник), `valid_at` (ISO-8601 дата/время с часовым поясом) и `license` (условия использования геоданных). Простая установка флага не доказывает правовую достоверность. Для публикации после модерации предусмотрен отдельный существующий инструмент `python -m server.wildlife <proposal>.json --id <unique-version-id>`.

Выходной файл запрещено перезаписывать. При отключённой сети CLI не получает живые данные. В тестах используются **синтетические** записи, они не добавлены в публичный пакет приложения.

## Открытые вопросы и ограничения

1. GBIF `occurrence/search` не гарантирует согласованный snapshot при изменении данных во время пагинации. Проверка total count снижает, но не устраняет риск. Для полной промышленной выгрузки нужен GBIF download API/снимок набора, журнал получения и контроль целостности.
2. Внутри ETL используется грубая консервативная оценка расстояния до границы (`*50 км/градус`), **не геодезический буфер**; нужен точный расчет расстояний на эллипсоиде и обработка пересечения 180-го меридиана для глобального применения.
3. Публикация смешанных лицензий в одном агрегате не обеспечивает полную traceability конкретных dataset/publisher/DOI. Для коммерческого выпуска требуется учёт provenance каждой записи и атрибуция всех источников; CC BY-NC исключена целиком, CC BY допустима только после должной атрибуции.
4. Признаки скрытия чувствительных видов у разных источников неоднородны; перед выпуском требуется отдельная модерация таксонов, политик конфиденциальности и степени детализации.
5. iNaturalist, официальные границы, система регуляторных статусов, спутниковые карты 1 м/пиксель и реальные пакетные карты пока не реализованы/не получены.
6. Не объявлять `source_record_url` доказательством юридической доступности охоты. Приложение в целом не прошло полевых испытаний.
