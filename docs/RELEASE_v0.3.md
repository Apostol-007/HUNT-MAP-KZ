# HUNT MAP KZ — MVP v0.3 (19.11.2026)

## Проверенные изменения

- Установка растровых MBTiles теперь выполняется **поблочными HTTP Range-запросами** по 4 MiB; незавершённый `.part` сохраняется между повторными попытками, в том числе после перезапуска.
- Каждый фрагмент принимается только при HTTP 206 и строго проверенном `Content-Range` (начальное смещение, конечное смещение, длина тела и общий размер).
- Запрос содержит `If-Range` с ожидаемым SHA-256/ETag. При смене содержимого сервер отвечает HTTP 200, что клиент отвергает вместо некорректного добавления в `.part`.
- После полного скачивания вычисляется SHA-256 всего файла, проверяется структура MBTiles, затем файл ставится на место пакета; неудачный файл не объявляется установленным.
- В интерфейс загрузок добавлены процент выполнения и действие «Скачать / продолжить».
- Сервер поддерживает HEAD, ETag, If-Range, частичные и суффиксные Range-ответы; отказ при нарушении целостности.

## Фактическая проверка в текущей среде Linux

- `cd Core && swift test`: **14 успешно** (6 XCTest + 8 Swift Testing).
- `python -m pytest -q server/tests`: **5 успешно**.
- Тесты Range покрывают смещение, длину, размер, невалидный и отсутствующий заголовок, последний короткий блок, смену ETag.
- **Не проверено:** компиляция iOS target, MapKit/SQLite3 на iPhone, загрузка больших реальных MBTiles на устройстве, фоновый GPS, скорость карты и автономность.

## Объективные ограничения

1. Карта в приложении пока **MapKit + собственный локальный MBTiles overlay**, не MapLibre. MapKit потенциально обращается к Apple за базовыми картами: строгий offline без сетевого трафика не доказан.
2. Загрузка «область / угодье / Казахстан» — только поиск опубликованных сервером пакетов по `scope`, а не формирование произвольного района. Пустой каталог не означает наличие покрытия.
3. Нет в комплекте юридически подтвержденных полигонов охотугодий, слоя ООПТ, путей и лицензированных спутниковых 1 м/пиксель.
4. Нет production-ETL видов/наблюдений, редактирования маркеров на карте, авторизации/облачного обмена.
5. Дедупликация перекрывающихся тайлов между отдельными MBTiles ещё отсутствует.
6. Если приложение убито системой или пользователем, фоновые уведомления о пересечениях **не гарантируются**.
7. Клиентская возобновляемая загрузка пока выполняется в активном процессе; фоновые загрузки через `URLSession` background не реализованы.
8. Сервер пересчитывает SHA-256 перед каждой выдачей, что безопасно для малых прототипов, но затратно для многогигабайтных пакетов. Для production требуется immutable object storage и доверенная публикация версий.
9. Пакетный реестр не имеет криптографической подписи: HTTPS и SHA-256 не дают полной независимой защиты от компрометации сервера.
