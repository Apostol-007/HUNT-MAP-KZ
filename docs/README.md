# Статус реализации HUNT MAP KZ, 19.11.2026

## Подтверждено тестами в текущей среде
- Swift 6.2.1 на Linux: 8 тестов HuntCore, в том числе сетка 1600 контрольных точек, отверстия в полигонах, переход через 180-й меридиан, GPS-гистерезис, фильтрация плохой точности и устаревших фиксов.
- FastAPI: 2 pytest-теста для каталога и скачивания Range, SHA-256, 416 и проверки повреждённых пакетов.

## Реализовано в исходниках, но сборка/поведение на iPhone не проверены
- Исходники SwiftUI iOS 17+ с 5 вкладками: Карта / Маршруты / Маркеры / Животные / Загрузки.
- CoreLocation и запрос фонового разрешения при старте записи; баннеры локальных предупреждений.
- Отрисовка локальной схемы полигонов, точек и треков в SwiftUI Canvas; **не настоящая топографическая карта**.
- Импорт локального GeoJSON Polygon/MultiPolygon с базовой валидацией (не выполняет GIS-проверку самопересечений).
- Начало, пауза, остановка записи, локальное JSON-хранение с атомарной записью, после сбоя трек переносится в историю как восстановленный.
- Добавление маркера по GPS, удаление маркеров, ссылка для обмена координатами, экспорт треков в GPX через Share Sheet.
- Демонстрационный синтетический полигон (отмечен как НЕ юридически достоверный).
- Публичный FastAPI прототип выдачи manifest и пакетов по HTTP Range.

## Не сделано и не выдаётся за рабочее
- MapLibre, PMTiles/MBTiles, фактическая офлайн-подложка дорог/троп/рельефа, снимки <=1 м/пиксель, построение/обновление карт по региону, угодью или всей стране.
- Правомерный и подтверждённый реестр границ Казахстана, государственные ограничения и юридически подтверждённые охотугодья.
- Обработка ETL GBIF/iNaturalist, офлайн-каталог животных, модерация, биологические данные.
- SQLite/RTree/PostGIS/PostgreSQL, серверная синхронизация, авторизация, live-share, групповой доступ, офлайн AirDrop-тесты.
- Возобновляемые клиентские загрузки, дедупликация тайлов, подписанные манифесты, полноценный менеджер пакетов.
- Полная защита данных, фоновый жизненный цикл iOS, производительные маршруты на 8 часов, UI тесты, инструментальные полевые испытания.
- 1000 реальных эталонных GIS-сценариев: сетка 1600 синтетических точек НЕ заменяет юридическую и геодезическую верификацию.

## Известные ограничения / риски кода
- iOS-код не компилировался: Xcode недоступен в этой Linux-среде. SwiftUI API, подпись, возможности фоновых режимов и entitlement необходимо проверить на Mac.
- GeoJSON импорт не верифицирует юридическую актуальность и топологию. Не использовать импорт как разрешение на охоту.
- Canvas показывает схему без топографической основы; рисует GPS/маркеры относительно динамического центра, панорамирование прототипное.
- Вычисление расстояния до коротких сегментов использует локальную плоскую аппроксимацию: длинные сегменты требуют геодезического уточнения.
- Производительность JSON-перезаписи всей истории при каждой GPS-точке ограничена; перед полевой эксплуатацией заменить SQLite append-only журналом.
- Локальные уведомления могут задерживаться ОС. Фоновая запись и предупреждения не проверены на реальном телефоне.
- Нужен audit геометрии и ограничений памяти на злонамеренных входных файлах.
- Сервер предназначен для локального прототипирования. Без токенов, TLS-терминации, rate limiting и производственного хранилища нельзя открывать публичный endpoint.

## Следующая проверяемая веха
1. На Mac установить Xcode и XcodeGen, сгенерировать проект и исправить возможные compile errors.
2. Подключить проверенный лицензированный офлайн векторный пакет MapLibre и один реальный легально доступный полигон.
3. Проверить настройки Background Modes, разрешения, локальные уведомления и locked-screen GPS на физическом iPhone.
4. Перевести треки и маркеры на SQLite, реализовать пакетный загрузчик, контрольные суммы на телефоне.

# HUNT MAP KZ v1.5.5 — поиск карт по выбранной точке

- Интерфейс карты и боковые элементы управления не переработаны.
- В окне точки добавлен запрос к выбранному HTTPS-каталогу `/v1/packs/at-point?lat=...&lon=...`.
- Сервер выбирает опубликованные MBTiles по полю `metadata.bounds` из SQLite, без выдуманного покрытия. Учитываются только существующие файлы с размером, совпадающим с манифестом.
- Доступные пакеты показываются с размером и лицензией; кнопка запускает прежний проверяемый SHA-256 загрузчик с докачкой.
- Если каталог не настроен или для точки нет пакетов, автоматическая загрузка невозможна. Произвольная нарезка тайлов не реализована.
- Google и Яндекс не используются для несанкционированного скачивания.

Проверка: `python -m pytest -q server/tests` — 25 passed. Полная сборка Xcode и физический iPhone не проверены.

**Сервер должен быть обновлён вместе с приложением.** Сторонние каталоги без `/v1/packs/at-point` могут продолжать работать через старый поиск по scope/id, но не через выбор точки.

# Сборка HUNT MAP KZ из Windows через GitHub Actions

## 1. Загрузите код

1. Распакуйте архив. Откройте папку `HUNT_MAP_KZ_MVP`.
2. Создайте **приватный** репозиторий GitHub; не выкладывайте пользовательские координаты и секреты.
3. Загрузите **содержимое** папки в корень репозитория (не ZIP как один файл).
4. Обязательно проверьте, что `.github/workflows/ios-unsigned.yml`, `iOS/project.yml`, `iOS/HuntMap` и `Core` на месте.

## 2. Запуск

GitHub -> Actions -> **iOS unsigned IPA** -> **Run workflow** -> ветка main -> **Run workflow**.

GitHub Actions запускает macOS c Xcode; локальный Mac/локальный Xcode на Windows не требуется.

В случае успешной сборки откройте завершившийся job -> Artifacts -> `HUNT-MAP-KZ-unsigned-IPA` -> скачайте ZIP с файлом `.ipa`.

Если сборка не прошла, скачайте `ios-build-log`, приложите лог к диагностике; ошибку исправляют в исходниках и повторяют workflow. **До реального успешного прогона IPA не считается проверенным.**

## 3. Как установить на iPhone без платной Apple Developer Program

`unsigned IPA` сам по себе не устанавливается. Его необходимо **подписать** своей бесплатной Apple Account через совместимый инструмент, например Sideloadly (Windows + USB + драйверы Apple) или AltStore. Это не официальная публикация в App Store. Бесплатная подпись обычно ограничена сроком действия и количеством приложений; установка, обновление и background capabilities могут зависеть от метода подписи. Для стабильной раздачи/TestFlight/публикации нужна платная программа разработчика и корректная подпись.

**Важно:** GitHub Actions не проверяет, что GPS и фоновые геозоны работают на реальном телефоне. Проверяйте на iPhone и сохраняйте диагностический отчёт.

## 4. Режимы карт

- **Онлайн:** в `Загрузки` включите `Онлайн-карта OpenFreeMap`. Требуется связь. Данные OSM не являются юридическими границами охотугодий.
- **Офлайн:** отключите онлайн-подложку, импортируйте свой лицензированный растровый `MBTiles` или скачайте пакет с настроенного HTTPS-сервера. Пустой фон без установленного пакета — ожидаемое поведение.
- **Границы:** GeoJSON с документальным источником; импорт не доказывает юридическую достоверность. Ссылки в приложении ведут к государственным источникам, но автоматического официального экспорта не обещают.
- **Животные:** `Животные` -> `Получить виды из GBIF · Казахстан`; загружается ограниченный список научных названий наблюдений. Это не список видов конкретного угодья. Проверенный каталог для конкретного угодья загружается отдельно.

## 5. Запись GPS и диагностика

1. Откройте `Карта` -> `GPS`, разрешите доступ к местоположению.
2. Нажмите `Запись`. При отсутствии разрешения появится сообщение, приложение не должно пытаться принудительно активировать фон.
3. Для фоновой записи iOS требует разрешение `Всегда`, Background Modes `location`, и корректную подпись. При разрешении `При использовании` запись возможна только при активном приложении.
4. Потрясите iPhone или откройте `Загрузки` -> `Диагностика`.
5. Используйте `Сохранить .txt` либо `Поделиться отчётом / ChatGPT`. Отправка через Share Sheet зависит от установленных приложений. Точные координаты скрываются.

## 6. Ограничения

- Без опубликованных и лицензированных наборов нет автоматического полного покрытия охотугодий и снимков 1 м.
- Нельзя массово скачивать тайлы с OSM публичных серверов; OpenFreeMap использовать согласно актуальным условиям сервиса.
- Проект требует первого реального CI прогона. До него сборка IPA не подтверждена.

# HUNT MAP KZ — MVP v0.3 (19.11.2026)

## Проверенные изменения

- Установка растровых MBTiles теперь выполняется **поблочными HTTP Range-запросами** по 4 MiB; незавершённый `.part` сохраняется между повторными попытками, в том числе после перезапуска.
- Каждый фрагмент принимается только при HTTP 206 и строго проверенном `Content-Range` (начальное смещение, конечное смещение, длина тела и общий размер).
- Запрос содержит `If-Range` с ожидаемым SHA-256/ETag. При смене содержимого сервер отвечает HTTP 200, что клиент отвергает вместо некорректного добавления в `.part`.
- После полного скачивания вычисляется SHA-256 всего файла, проверяется структура MBTiles, затем файл ставится на место пакета; неудачный файл не объявляется установленным.
- В интерфейс загрузок добавлены процент выполнения и действие «Скачать / продолжить».
- Сервер поддерживает HEAD, ETag, If-Range, частичные и суффиксные Range-ответы; отказ при нарушении целостности.

## Фактическая проверка в текущей среде Linux

- `cd Core && swift test`: **14 успешно** (6 XCTest + 8 Swift Testing).
- `python -m pytest -q server/tests`: **5 успешно**.
- Тесты Range покрывают смещение, длину, размер, невалидный и отсутствующий заголовок, последний короткий блок, смену ETag.
- **Не проверено:** компиляция iOS target, MapKit/SQLite3 на iPhone, загрузка больших реальных MBTiles на устройстве, фоновый GPS, скорость карты и автономность.

## Объективные ограничения

1. Карта в приложении пока **MapKit + собственный локальный MBTiles overlay**, не MapLibre. MapKit потенциально обращается к Apple за базовыми картами: строгий offline без сетевого трафика не доказан.
2. Загрузка «область / угодье / Казахстан» — только поиск опубликованных сервером пакетов по `scope`, а не формирование произвольного района. Пустой каталог не означает наличие покрытия.
3. Нет в комплекте юридически подтвержденных полигонов охотугодий, слоя ООПТ, путей и лицензированных спутниковых 1 м/пиксель.
4. Нет production-ETL видов/наблюдений, редактирования маркеров на карте, авторизации/облачного обмена.
5. Дедупликация перекрывающихся тайлов между отдельными MBTiles ещё отсутствует.
6. Если приложение убито системой или пользователем, фоновые уведомления о пересечениях **не гарантируются**.
7. Клиентская возобновляемая загрузка пока выполняется в активном процессе; фоновые загрузки через `URLSession` background не реализованы.
8. Сервер пересчитывает SHA-256 перед каждой выдачей, что безопасно для малых прототипов, но затратно для многогигабайтных пакетов. Для production требуется immutable object storage и доверенная публикация версий.
9. Пакетный реестр не имеет криптографической подписи: HTTPS и SHA-256 не дают полной независимой защиты от компрометации сервера.

## Следующая необходимая работа

- Встроить и собрать MapLibre Native с проверенным API локальных источников, полностью исключить MapKit online fallback; затем проверить сетевой трафик в режиме Strict Offline.
- Подготовить **лицензионно разрешённый** демо-набор карт и **авторитетный** источник охотграниц с датой проверки.
- Реализовать полнофункциональный менеджер карт: выбор полигона, пауза, фоновые загрузки, storage accounting, удаление/дедупликация.
- Испытать CoreLocation на реальном iPhone 2/4/8 часов с блокировкой экрана и авиарежимом.

**Статус: проверен протокол переноса и Swift-геометрия; приложение не готово для полевой навигации.**

# HUNT MAP KZ v0.7 — GBIF candidate ETL

Дата: 19.11.2026. Статус: предварительный ETL-процесс, не опубликованная база животных. Сборка iOS на macOS/Xcode и полевые испытания отсутствуют.

## Изменения

- Отсекаются записи без явной CC0/CC BY лицензии, с отсутствующей погрешностью, чрезмерной неопределённостью (по умолчанию более 1000 м), ошибками координат, метками скрытия, сомнительным таксоном, дубликаты GBIF key, записи вне границы или в буферной зоне.

- Выход: `<output>.json` и `<output>.review.json`; автоматическая публикация на API **не производится**. Необходим человек-модератор, проверка правообладателей/атрибуции, политик чувствительных видов, качества границы и необходимости исключить отдельные виды.
- В `server/requirements.txt` добавлена библиотека Shapely с фиксированной версией.

## Запуск

Из корня каталога проекта:

```bash
python -m pip install -r server/requirements.txt pytest httpx
python -m pytest -q server/tests
python -m server.gbif_etl --boundary /path/to/verified-ground.geojson --output /path/to/gbif-proposal.json --max-records 1000
```

`verified-ground.geojson` должен быть GeoJSON Feature с Polygon/MultiPolygon, Properties: `ground_id` (строка), `boundary_verified: true` (после **реальной ручной проверки**), `source_url` (официальный HTTPS-источник), `valid_at` (ISO-8601 дата/время с часовым поясом) и `license` (условия использования геоданных). Простая установка флага не доказывает правовую достоверность. ## Открытые вопросы и ограничения

1. GBIF `occurrence/search` не гарантирует согласованный snapshot при изменении данных во время пагинации. Проверка total count снижает, но не устраняет риск. Для полной промышленной выгрузки нужен GBIF download API/снимок набора, журнал получения и контроль целостности.
2. Внутри ETL используется грубая консервативная оценка расстояния до границы (`*50 км/градус`), **не геодезический буфер**; нужен точный расчет расстояний на эллипсоиде и обработка пересечения 180-го меридиана для глобального применения.

5. iNaturalist, официальные границы, система регуляторных статусов, спутниковые карты 1 м/пиксель и реальные пакетные карты пока не реализованы/не получены.
6. Не объявлять `source_record_url` доказательством юридической доступности охоты. Приложение в целом не прошло полевых испытаний.
