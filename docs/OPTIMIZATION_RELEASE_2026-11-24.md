# HUNT MAP KZ — аудит и оптимизация 24.11.2026

**Версия исходников:** 5.9.1 (65). **Назначение:** сохранить все возможности iOS, уменьшить блокировки UI и усилить сохранность GPS/офлайн-данных.

## Статусы, не смешивать

- **В исходниках:** наличие реализации подтверждено анализом файлов в репозитории.
- **CI:** Swift Core, сервер, карта-утилиты, статические контракты и компиляция IPA должны проходить в GitHub Actions. Зелёная сборка не проверяет GPS, навигацию и графику на физическом iPhone.
- **Устройство:** нельзя считать проверенным без холодного запуска, офлайн-проверки и журнала iOS.
- **Пограничные/юридические сведения:** реальные границы охотугодий требуют достоверного источника и геодезической/правовой верификации. Их нельзя синтезировать из охвата карт.

## Реализовано в репозитории

1. **Запуск:** MapLibre создаётся при открытии карты; долгие проверки сети и пакетов не блокируют первый экран; LaunchHealth хранит безопасный диагностический маркер прерванного запуска.
2. **GPS:** `TrackPointJournal.swift` пишет новые GPS-фиксы в SQLite WAL, JSON остаётся для совместимости и экспорта. Отдельная мета-таблица `active_track` позволяет восстанавливать запись, если `field.json` отсутствует или не декодируется. Нечитаемый JSON сначала копируется в файл аварийного восстановления. Журнал очищается только после подтверждённой записи восстановленного маршрута.
3. **Маршрутизация:** Valhalla и GeoJSON fallback; fallback загружает граф вне главного потока, GPS-отклонение от маршрута проверяет расстояние до сегмента и гистерезис.
4. **Картография:** офлайн MBTiles/PMTiles и отдельные ресурсы стиля; MapLibre на отдельной поверхности под погодными слоями; SQLite MBTiles переиспользует read-only соединения, данные пакетов проходят размер/хеш/формат-проверки.
5. **Пакеты:** повторные SHA-256 на главном потоке заменены реестром проверенных квитанций с контролем mtime/размера и сроком повторной проверки; сама проверка хеша больших файлов выполняется в фоновом потоке.
6. **Погода:** частичная сетка отрисовывается по доступным узлам; последний кеш остаётся до нового прогноза; отменённые запросы не могут сбросить состояние новой загрузки (generation token).
7. **CI:** Swift Core + FastAPI + Python офлайн-картография + статический контроль iOS-конфигурации/UI + сканирование секретов рабочего дерева. IPA — отдельный macOS этап для `[release]` и ручного запуска, чтобы обычный push не тратил время macOS.

## Не считать завершённым до проверок

- **Реальный холодный запуск и отсутствие crash/watchdog** на актуальном iPhone/iOS. Проверить после обновления поверх установленной версии, без удаления пользовательских данных.
- **Действительная отрисовка PMTiles** с `pmtiles://`: генерация style JSON не эквивалентна регистрации протокола в MapLibre.
- **Все три погодных слоя** на устройстве, в т. ч. 0 мм/ч осадков как штатное пустое поле, и результат `painted/visible` в отчёте.
- **Фоновая GPS-запись** с заблокированным экраном, переход через границы, защита от пропущенных/ложных уведомлений.
- **Длительное ведение по маршруту и запись более 8 часов**, перестроение и правильное воспроизведение в обе стороны. Нет подтверждённого профиля Instruments для времени/памяти/энергии.
- **Миграция всей исторической базы из JSON в SQLite**: выполнен SQLite append-only журнал активной записи, но остальной архив сознательно сохраняется в старом формате ради безопасной совместимости.
- **Точный охват дорог/троп:** `OfflineRoadOverlayStore` имеет защитные лимиты по пакетам, линиям и вершинам, поэтому большие области могут отображаться частично.
- **Проверка истории Git на токены**: текущий workflow сканирует только текст файлов рабочего дерева.
- **Юридические границы и их топология**: необходимы проверенные источники, независимая валидация и метаданные.

## Протокол приёмки версии

1. Сохранить резервную копию данных через `Ещё → Резервная копия`, обновить IPA **поверх** существующего приложения.
2. Холодный запуск трижды: экран доступен, нет самопроизвольного закрытия; затем открыть карту, включить офлайн и проверить тайлы, маркеры, масштаб и стиль.
3. Открыть слои `Ветер / Давление / Осадки` и проверить `Weather render status`; проверять не только HTTP 200, но и ненулевой размер canvas и число реально окрашенных ячеек.
4. Начать GPS-запись, оставить приложение в фоне и с заблокированным экраном, прервать процесс, перезапустить и проверить восстановление без дублирования трека.
5. Проверить пеший и автомобильный маршрут Valhalla, fallback при отсутствии TAR, отклонение с возвращением и прохождение сохранённого трека с начала/конца.
6. Проверить загрузку повреждённого и оборванного пакета, повторную попытку, неизменность существующих файлов и работу без интернета.
7. Запустить Instruments: Time Profiler / Allocations / Energy Log; зафиксировать baseline и сравнить с предыдущей IPA. Пока этих чисел нет — проценты ускорения не заявлять.

## Архитектурные работы следующего безопасного этапа

Полный SQLite-архив сохранённых треков и геозон, сегментированный пространственный индекс дорог, полное разделение `WeatherGridService` на Provider/Repository/Renderer, декомпозиция `MainView.swift` и инструментальные UI/snapshot tests. Выполнять с тестами обратной совместимости; перед выпуском не менять одновременно формат данных и географическую модель.
