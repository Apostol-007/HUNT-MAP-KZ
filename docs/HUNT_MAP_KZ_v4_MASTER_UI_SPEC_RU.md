# HUNT MAP KZ — MASTER UI/UX ТЗ v4.0

**Статус:** утверждаемый визуальный эталон по присланному пользователем макету из восьми экранов, 23.11.2026. **Базовая ветка для патчей:** исходники v3.1 поверх v3.0 и v2.5. Язык интерфейса: русский. Платформа: нативное приложение iOS 17+, SwiftUI, картографический движок MapLibre Native (возможность замены на MapTiler SDK Swift после проверки офлайн-контракта). Не подменять реальную функциональность демонстрационным наполнением.

## 1. Неподвижный эталон

Эталонный файл внутри репозитория: `docs/ui_reference_8screens.png`. Исходный макет содержит восемь вариантов экрана в порядке чтения: «Главная», «Карта», «Слои карты», «Погода», «Маршруты», «Метки», «Животные», «Ещё». Визуальная спецификация: фон почти чёрный, графитовые карточки, ярко-зелёный активный цвет, лёгкие зелёные ореолы, белая типографика, округлые элементы, отсутствие длинных форм на главных экранах. Макет задаёт расположение элементов и визуальную иерархию, но **не является источником фактических координат, погодных значений, статистики, юридического статуса животных или границ**.

## 2. Навигационная архитектура

Нижняя панель: **Главная** → **Карта** → **Данные** → **Сервисы** → **Ещё**. В «Данные» экраны «Маршруты» и «Метки». В «Сервисы» «Погода» и «Животные». «Слои карты» — bottom sheet из карты. Нижняя навигация остаётся во всех основных разделах, поверх карты. Переход не уничтожает экземпляр карты, GPS-сессию или запись трека.

## 3. Экран 1. Главная

- Логотип HUNT MAP KZ (оригинальный проектный знак, не копировать банковскую символику), подпись «Охота · Карты · Навигация», кнопка состояния/уведомлений.
- Баннер с природой/охотугодьями, заголовком «Карты охотугодий Казахстана», статусом «Офлайн · GPS · Границы»; фотография только с разрешением на использование, до её появления — качественная собственная графика без вымышленных изображений.
- Точки пагинации баннера **только если есть минимум две реально действующие карточки**.
- Сетка 2×2: «Карта и охотугодья», «Загрузить карты», «Мои маршруты», «Слои и погода». Каждая плитка открывает работающий модуль.
- «Мои данные»: число сохранённых маршрутов, меток, импортированных охотугодий из хранилищ; никаких цифр-заглушек.

## 4. Экран 2. Карта

- `MLNMapView` занимает все окно iPhone, включая экран под status bar и home indicator; нельзя помещать карту в ScrollView, TabView с ограничениями или контейнер фиксированной высоты.
- Вверху прозрачная тёмная строка поиска по локальным угодьям и маркерам с рабочим поиском, кнопка слоёв.
- Справа вертикальные действия: слои, погодный слой, GPS; плюс/минус масштаба доступны только при наличии корректной связи с картой.
- Выделение угодья: заливка зелёная прозрачная, обводка ярко-зелёная; тап по полигону открывает карточку с **всеми атрибутами источника**, названием, проверенностью, датой/лицензией если есть.
- GPS-точка, метки, активная запись маршрута, масштаб, режим карты. Режимы: спутник MapTiler при встроенном API-ключе, Outdoor, Streets, OpenFreeMap и локальный офлайн. Русский язык вектора: `name:ru`, затем `name`, затем `name:en`.
- Нижние операции: «Моя позиция», «Добавить метку», «Запись маршрута» и «Завершить»; GPS без разрешений не должен аварийно завершать приложение.
- Плашки управления занимают минимальную долю дисплея, область карты остаётся интерактивной.

## 5. Экран 3. Слои карты

Строго шесть карточек: «Охотугодья», «Рельеф», «Спутник», «Топографическая», «Погода», «Животные». Иконка слева, название, описание, реальный переключатель справа. **Недопустимо показывать активный переключатель для нереализованного слоя:** для животных без геоданных и правомерного покрытия — disabled/информация; для рельефа без проверенного DEM переключатель остаётся недоступным, а топографическая включает Outdoor. Кнопка «Закрыть» фиксирована внизу. Выбранные состояния сохраняются.

## 6. Экран 4. Погода

- Отображаемая область по GPS или выбранной координате, карточка большой температуры и условий; отдельные текущие значения ветра, давления, осадков, влажности.
- Горизонтальная почасовая лента с настоящими значениями Open-Meteo и выбранным временем. Не придумывать облачность из отсутствующего weathercode: если код отсутствует — нейтральная пиктограмма и пояснение.
- Четыре строки: «Прогноз на несколько дней» (если API поддерживает), «Карта ветра», «Карта осадков», «Карта давления». Каждая открывает реальный функциональный экран или сообщает об отсутствии пространственных данных.
- Сетка погодных данных может быть интерполирована только внутри полученной области. Прогноз не называть радаром. Кэш маркировать временем и источником.

## 7. Экран 5. Маршруты

- Заголовок «Маршруты», основная зелёная кнопка «Новый маршрут».
- Фильтры «Все», «Активные», «Архив». История из настоящего `FieldModel`, текущая запись — Active; архив — завершённые треки.
- Карточка: тип маршрута/имя, длина в км, длительность по UTC timestamps точек, дата, действия поделиться GPX, удалить после подтверждения если модель поддерживает безопасное удаление.
- Запись / пауза / завершение: сохранившаяся логика GPS; отчёт об отказе в разрешении вместо вылета.

## 8. Экран 6. Метки

- Заголовок «Метки», зелёная кнопка «Добавить метку».
- Фильтры: Все, База, Зверь, Кормушка, Другое; маркеры группируются по сохранённому `kind` или `symbol`, непонятные типы относятся к «Другое».
- Карточки с подходящими пиктограммами и цветовыми акцентами, названием и координатами, меню: поделиться, открыть на карте, изменить, удалить.
- Источник данных: текущая сохранённая модель Marker. Никаких демонстрационных GPS-точек.

## 9. Экран 7. Животные

- Переключатель «По угодьям» / «Справочник».
- Данные берутся из импортированных/проверяемых локальных пакетов и GBIF. Показывать русское и научное название, статус подтверждения, источник, дату записи.
- Фотографии добавлять лишь при наличии разрешённых источников с атрибуцией. Снежный барс/косуля/кабан/сурок на макете — пример карточек, не разрешение считать их обитающими в выбранном хозяйстве.
- Никаких точных координат редких видов в публичном каталоге. Юридическое разрешение на добычу выводится только из отдельного официально подтверждённого источника.

## 10. Экран 8. Ещё

- Пять строк: «Загрузки карт», «Диагностика», «Настройки», «Синхронизация», «О приложении».
- Все строки открывают реальные разделы; «Синхронизация» должна показывать состояние и предложить доступное обновление, а не имитировать успешную загрузку.
- Внизу оригинальный логотип и фактический `CFBundleShortVersionString`/build из Info.plist.
- «Диагностика» по встряхиванию телефона или через меню, редактируемый/экспортируемый текстовый отчёт без точных координат по умолчанию.

## 11. Источники и безопасность

- Карты: MapLibre / MapTiler, только лицензированные тайлы. API-ключ через GitHub Actions Secret `MAPTILER_API_KEY` и `Info.plist` при сборке; **не коммитить секрет в код**. Встроенный в IPA ключ не секретен — ограничивать квоты/доступ.
- Охотугодья: проверяемый GeoJSON/WFS/ArcGIS сервис только после установления прав и схемы, Tabigat — при наличии разрешённого интерфейса. Пока официальный источник не подтверждён, не демонстрировать недостоверные границы.
- Животные: локальные JSON-пакеты + GBIF, проверка лицензий и географического контекста.
- Погода: Open-Meteo; корректная атрибуция, время и единицы измерения.
- Офлайн: явное отображение установленных карт, индикатор доступа к сети и сохранённого прогноза. Нельзя выдавать открытые онлайн-тайлы за скачиваемый офлайн-пакет.

## 12. Проверяемые критерии приёмки

1. По каждому из восьми экранов в точности воспроизводится иерархия визуального эталона: расположение, размеры, цвет, активные состояния, поведение прокрутки.
2. На iPhone карта физически занимает bounds окна: minX/minY 0±1 pt, ширина/высота равны окну ±1 pt; тест на устройстве по диагностике.
3. Нет автоматической вставки вымышленных данных и числа статистики всегда соответствуют локальным моделям.
4. Каждая активная кнопка отвечает действием, сетевые функции показывают состояние загрузки и ошибку, не зависают.
5. Серверные/Swift Core тесты проходят; полный Xcode `xcodebuild` для iPhone SDK завершается `BUILD SUCCEEDED`; артефакт unsigned IPA формируется.
6. Тест на реальном iPhone: запуск, карта, разрешения GPS, запись/пауза/стоп, метка, закрытие sheets, сохранение, импорт, погода, поиск, устойчивость без сети.
7. В релизе: ZIP с **только изменёнными/новыми файлами**, сохранение каталогов GitHub, `PATCH_README.md`, список удалений, базовая версия и список непроверенных возможностей. Полный исходный архив — только по отдельному запросу.

## 14. Реализация патча v4.0 (23.11.2026)

**Базовая версия:** последовательно установленные исходники v2.5 → v3.0 → v3.1.

Сделано на уровне исходников: новая дизайн-система и восемь экранов, пятираздельная навигация, главные карточки, полноэкранная карта, локальный поиск, масштабирование и центрирование GPS, слои карты (без неподтверждённого 3D-рельефа), сохранение видимости границ, фильтры маршрутов и меток, меню редактирования/удаления/экспорта, погодная сводка и почасовые данные, животные из подтверждаемых каталогов, раздел «Ещё», подключение к диагностике. Референсный макет сохранён рядом с ТЗ.

Частично: изображения главного баннера и животных требуют лицензионных изображений; спутниковая карта требует MapTiler API ключа и доступа; «Синхронизация» ведёт в существующий расширенный экран инструментов, а не отдельный мастер; для погодной сетки нужен сервер. Точная визуальная близость будет подтверждена только Xcode/snapshot-тестами.

Не реализовано/не подтверждено: рельеф DEM/3D; официальная автоматическая загрузка Tabigat без подтверждённого API, отдельный пространственный слой животных (кнопка недоступна), 7-дневный прогноз как самостоятельный экран, физическая полноэкранность и сборка IPA на iPhone, лицензированные фотографии.

Проверки в среде разработки: Swift Core 24 XCTest + 11 Swift Testing; Python сервер 34/34; Swift синтаксис; регрессионные проверки структуры UI и метаданных. Это не равно полной компиляции Xcode.

### Применение изменений к GitHub

1. Основа репозитория должна содержать v3.1 поверх v3.0 поверх v2.5 (см. историю проекта).
2. Распаковать ZIP-патч с сохранением путей и заменить перечисленные файлы. Новые файлы добавить. **Не удалять другие файлы, не загружать ZIP как отдельный файл в корень GitHub.**
3. Список файлов для удаления по этому патчу: **нет**.
4. Убедиться, что настроен секрет `MAPTILER_API_KEY` в GitHub Actions.
5. Запустить `HUNT MAP KZ - unsigned iOS IPA` и проверить `BUILD SUCCEEDED`, затем на iPhone сопоставить восемь экранов с `docs/ui_reference_8screens.png` и отправить скриншоты/диагностику для устранения расхождений.
